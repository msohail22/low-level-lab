## Description

Consider this line, where `p` may or may not be null:

```cpp
delete p;
```

True or false: if `p` is a null pointer, this line is safe and does nothing.

<Choices />

<Answer>

True. The standard says that if the pointer passed to `delete` is null, the
operation has no effect. You do not need to guard it, so the null check here buys
you nothing:

```cpp
if (p != nullptr) {   // redundant
  delete p;
}
```

The confusion comes from a reasonable generalisation. Dereferencing a null pointer
is undefined, so people assume every operation on null is. `delete` is carved out as
an exception, specifically so cleanup code does not need null checks scattered
through it.

```
delete p
   ├── p == nullptr ──────▶ do nothing              ← defined, safe
   ├── p from new ────────▶ destructor, then free   ← defined, correct
   ├── p already deleted ─▶ UNDEFINED               ← double free
   └── p from malloc ─────▶ UNDEFINED               ← mismatched allocator
```

Deleting the same non-null pointer twice is a double free and is undefined. So is
mixing allocators. `std::unique_ptr` avoids the question entirely: it deletes once,
at the right time, and nulls itself when moved from.

</Answer>
