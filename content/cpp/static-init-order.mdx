## Program

Read this and write down exactly what it prints, including the order of the lines.

```cpp
#include <iostream>

int counter() {
  static int n = 0;   // note: static
  return ++n;
}

struct Noisy {
  Noisy()  { std::cout << "ctor\n"; }
  ~Noisy() { std::cout << "dtor\n"; }
};

Noisy& instance() {
  static Noisy n;     // constructed on first call, never again
  return n;
}

int main() {
  std::cout << counter() << "\n";
  std::cout << counter() << "\n";
  instance();
  instance();
  std::cout << "end of main\n";
  return 0;
}
```

<Answer>

```text
1
2
ctor
end of main
dtor
```

</Answer>

## Explanation

Two separate rules are at work, and both come from the word `static` on a local
variable.

**The variable is initialised once, not once per call.** A `static` local lives for
the whole program, not for the call. So `static int n = 0;` runs the `= 0` exactly
once, on the first call. `counter()` therefore prints 1 then 2, not 1 then 1.

**Initialisation happens on first use, and destruction at exit.** `static Noisy n;`
inside `instance()` is not constructed when the program starts. It is constructed the
first time control reaches that line. The second `instance()` call skips it entirely
— hence one `ctor`, not two. The destructor runs after `main` returns, which is why
`dtor` comes *after* `end of main`.

```
time ────────────────────────────────────────────────────▶

counter()   n=0 created, ++n → 1        prints 1
counter()   n already exists, ++n → 2   prints 2
instance()  n not yet built → ctor      prints ctor
instance()  n already built → skipped   prints nothing
main returns                            prints end of main
static destructors run                  prints dtor
```

Everyday comparison: a shop's "open" sign. It is put up the first morning someone
opens the shop, not when the building was built, and it is taken down only when the
business closes for good — after the last customer has left.

This lazy-and-once behaviour is why `static` locals are the standard way to write a
singleton in C++. It also fixes the static initialisation order problem: a global
object's construction order across translation units is unspecified, but a `static`
local is guaranteed to be built before the first use, because the first use is what
builds it.
