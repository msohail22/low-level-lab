## Description

Write down exactly what this program prints, including the order of the lines.

```cpp
#include <iostream>

int counter() {
  static int n = 0;   // note: static
  return ++n;
}

struct Noisy {
  Noisy()  { std::cout << "ctor\n"; }
  ~Noisy() { std::cout << "dtor\n"; }
};

Noisy& instance() {
  static Noisy n;
  return n;
}

int main() {
  std::cout << counter() << "\n";
  std::cout << counter() << "\n";
  instance();
  instance();
  std::cout << "end of main\n";
  return 0;
}
```

<Answer>

```text
1
2
ctor
end of main
dtor
```

Two rules are at work, both from the word `static` on a local variable.

A `static` local is initialised once, not once per call. It lives for the whole
program, so `static int n = 0;` runs the `= 0` exactly once. `counter()` prints 1
then 2.

A `static` local is built on first use and destroyed at exit. `static Noisy n;` is
not constructed when the program starts, but the first time control reaches that
line. The second `instance()` call skips it, so there is one `ctor`, not two. The
destructor runs after `main` returns, which is why `dtor` comes after `end of main`.

```
counter()   n created, ++n → 1       prints 1
counter()   n exists, ++n → 2        prints 2
instance()  n not yet built → ctor   prints ctor
instance()  n already built          prints nothing
main returns                         prints end of main
static destructors run               prints dtor
```

This lazy-and-once behaviour is why `static` locals are the standard way to write a
singleton in C++, and why they dodge the static initialisation order problem: the
first use is what builds the object.

</Answer>
