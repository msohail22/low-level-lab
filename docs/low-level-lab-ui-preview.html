Two threads, two variables, one slow program

Each thread increments its own counter. They never share data. The program still runs four times slower than the single-threaded version. Explain why.

Start with the layout. Both counters were declared next to each other, so the linker put them in the same sixty-four byte cache line. Nothing in the source says the threads share anything, but the hardware does not track variables. It tracks lines.

// both counters land inside one cache line struct counters { long a; // thread 0 writes here long b; // thread 1 writes here };
When thread zero writes to a, the coherence protocol invalidates that line everywhere else. Thread one's next write to b misses, pulls the line back, and invalidates thread zero in turn. The line ping-pongs between cores for the whole run.

The threads are not sharing a variable. They are sharing a line, and the line is the unit that moves. The fix is padding: push each counter onto its own line, and the traffic disappears.
